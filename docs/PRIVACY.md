# Privacy

## Current behavior

- Filename collision preference defaults to Rename. Ask shows filesystem conflicts known before queueing and lets the user cancel, rename, or replace; if a server later supplies a conflicting Content-Disposition filename, BestDM automatically chooses a safe suffix. Overwrite replaces an existing unmanaged output only after the new transfer succeeds. The preference is saved in QSettings and per-task overwrite intent in SQLite. Existing BestDM task paths remain reserved so their history does not silently point to replaced content.

- BestDM does not currently include analytics, account sign-in, cloud sync, remote task-history upload, update checking, or a browser bridge.
- Added HTTP/HTTPS URLs, filenames, destination paths, transfer state, validators, byte counts, retry count, and timestamps are stored locally in the SQLite database under the operating system's application-data directory. The SQLite file is not encrypted by BestDM.
- URLs with embedded user information are rejected. Manual proxy passwords are stored per proxy endpoint in Windows Credential Manager and are never written to QSettings or SQLite. System proxy credentials are not imported. Other platforms currently support proxy settings without saved proxy passwords. Query strings in signed URLs may still be required for the download and are stored locally with the URL; users should treat the local database as sensitive.
- HTTP origin authentication is prompted when a server returns a username/password challenge. Credentials are passed to Qt Network's authenticator and retained in application memory only for the current session, keyed by task and canonical `(scheme, host, port)` origin. A redirect to another origin cannot reuse them and requires a separate prompt. They are not saved in SQLite, QSettings, or logs. Closing the prompt leaves the download failed for the user to retry later.
- HTTP(S) requests use Qt Network and retain TLS certificate validation. Requested file bytes are written locally to `.part` files and then finalized in the selected folder.
- Optional clipboard monitoring is disabled by default and can be enabled in Settings. When enabled, BestDM reads clipboard text locally, recognizes a single HTTP/HTTPS URL, and asks whether to open the Add dialog. It never queues a link without user action; clipboard contents are not transmitted or persisted by this feature.
- Completion/failure notifications are controlled by a local setting and contain only the filename. The optional system-tray icon and menu stay on the device; no task information is sent to a BestDM service.
- Optional open-file/open-folder completion behavior is selected and run locally through the operating system's file association; it does not send task details to a BestDM service.
- The optional custom completion program is user-selected and runs locally through `QProcess` without shell interpretation. BestDM passes the completed file path as one argument; the program may access that file under the operating system account's permissions.
- Optional Windows shutdown, sleep, and hibernate actions are disabled by default. They require a queue-completion prompt, a separate confirmation, and a cancelable 60-second countdown; no power action runs from restored history alone.
- Optional Microsoft Defender scanning is disabled by default and runs locally on each completed file before other completion actions. The file path is passed as a separate process argument; no file contents or task metadata are sent to a BestDM service. Defender may require BestDM to run elevated according to Windows policy.
- Optional `bestdm://` registration is disabled until selected in Settings and writes a per-user Windows registry handler. Links are limited to one validated HTTP(S) URL and are forwarded over a per-user local socket to the running app. They only populate the Add dialog and do not enqueue downloads automatically.
- BestDM does not call a BestDM-hosted service. It can launch the user-selected completion program, and on Windows it can launch the installed Microsoft Defender command-line scanner when those options are explicitly enabled; these processes receive only the file path and execute locally under the user's account/policy.
- Qt operational messages are written to a local rotating log under the OS application-local data directory (`logs/bestdm.log` plus up to three 1 MiB backups). HTTP(S) URL user information, fragments, and query strings are removed/redacted; authorization, cookie, password, token, API-key, secret fields, and the current user's home path are redacted. Log files remain on the device and may contain ordinary local error details. Log redaction/rotation tests are authored but not yet run.
- Users can explicitly export redacted diagnostic logs from Settings to a selected local `.txt` file. The export contains only the rotating log files; it excludes the SQLite database, download list, and downloaded files. Export re-applies redaction and never uploads data.

## Planned disclosure work

Before release, document database location/retention, deletion behavior, system/manual proxy behavior, Windows Credential Manager storage, update checks, browser pairing, and external media tools. Run the log-redaction and user-selected export tests before implementing any feature that handles cookies, credentials, or signed URLs.
