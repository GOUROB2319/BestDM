- Added confirmed Remove choices for every task: remove its database/list entry while preserving files, or delete the completed and partial file before removing the entry. - Added an opt-in Windows Defender file scan using the installed `MpCmdRun.exe` and documented `-Scan -ScanType 3 -File <path>` arguments. It runs before the configured open/custom-program action; nonzero exits, start failures, and a 30-minute timeout prevent that action. The executable is located in current Windows Defender platform folders or the legacy installation path. Microsoft documents elevated command prompt use; BestDM reports scan failure if current permissions/policy do not allow it, shows an app dialog or tray notification, and cancels a scan if its task is removed. Runtime and Defender-policy behavior remain unverified.
- Added opt-in Windows shutdown, sleep, or hibernate after queue completion. A successful completion in the current queue session triggers a confirmation dialog; a second user action starts a 60-second cancelable countdown. New work cancels a pending action, and previous completed history alone cannot trigger it. Suspend API calls run off the UI thread; Windows runtime and power-permission behavior are pending verification.
- Added local `.txt` URL-list import through a Qt file picker. C++ enforces UTF-8 and 1 MiB bounds, then feeds the imported lines through the existing batch review before enqueue.
- Added optional, default-off clipboard URL monitoring. It accepts only one HTTP/HTTPS link at a time, prompts before opening Add, and never queues automatically; the setting and privacy behavior are documented.
- Added a native system tray with Open/Quit actions, window restore, optional minimize/close-to-tray, and configurable filename-only completion/failure notifications. Tray availability gates hide-to-tray behavior; runtime verification remains pending.
- Added per-task destination changes for queued, waiting, paused, canceled, failed, and completed tasks. Existing output, partial, and segment files move to the selected existing writable folder (copy fallback supports cross-volume moves) with rollback on failure; target-name conflicts reserve a safe collision-free name, and selecting a per-task folder disables automatic category subfolders for that task. Runtime and filesystem-failure verification remain pending.
- Added HTTP `Retry-After` handling for 429/503 responses. Retry-After delay-seconds and HTTP dates are persisted as queue deadlines, capped at 24 hours, and combined with exponential backoff; runtime verification remains pending.
- Metadata probes now retain a validated final HTTP(S) redirect URL in schema v8; download details display that URL with sensitive query values redacted while preserving the original source URL for future requests.
- Added configurable per-download connection counts and a `SegmentedDownloader`: it resumes independently stored ranges, validates response status/range/size/validators, uses the shared bandwidth limiter, merges through `QSaveFile`, and falls back to single-stream when range behavior is not valid. Segment files are included in pause/cancel cleanup, startup recovery, and filename collision checks; runtime verification remains pending.

## Current status and limitations

- 2026-10-13: Added Windows per-user `bestdm://` registration through HKCU, opt-in in Settings, strict `bestdm://add?url=<HTTP(S)>` validation, and a user-scoped `QLocalServer` single-instance forwarder. Forwarded and startup links restore the main window and fill the normal Add dialog; no download starts without the user's Add action. Registration ownership, local-socket ACL, URI edge cases, and end-to-end behavior remain unverified.
- 2026-10-13: Added a History-only Clear history action that resolves to one confirmation with independent keep-files and delete-files choices. It uses the existing queue removal path, so failed file cleanup retains its task and surfaces the error. UI and filesystem behavior remain unverified.
- 2026-10-13: Added named download queues: create/select queues, route new links into the selected queue, filter tasks and sidebar counts by queue, move selected tasks between queues, and persist queue definitions/selection in QSettings plus each task's assignment in SQLite schema v11. Queues share the global concurrency limit. Migration, sorting/filter combinations, and runtime behavior remain unverified.
- 2026-10-13: Added destination free-space preflight for known-size single-stream downloads and segmented downloads (including room for the final atomic merge). Stream/segment write, flush, and merge failures report disk-space or storage errors while retaining recoverable partial data; single-stream disk-write failures are excluded from transient network retries. Free-space estimates can change during concurrent writes, and compile/runtime/disk-full behavior remain unverified.
- 2026-10-13: Follow-up failure-path audit makes a flush failure override an earlier transient network error in both transfer modes, disables retry, and prevents a failed flush during pause from being reported as a successful pause. Runtime behavior remains unverified.
- 2026-10-13: Startup recovery now reschedules persisted `Retrying` tasks using their stored deadline. Incomplete records recreate a missing destination folder when possible; empty, non-directory, non-writable, or uncreatable destinations are persisted as Failed with a retry instruction. Paused entries reconcile their received-byte count against existing partial/segment files, and explain when resume will restart from zero. Restart and permission behavior remain unverified.
- 2026-10-13: Final publication handles a filename claimed during transfer by selecting the next collision-free suffix and using a platform no-replace operation (Windows `MoveFileW`, Unix hard-link creation followed by partial unlink). An explicitly selected Overwrite policy uses atomic replacement after successful verification; failures preserve the old output. Filesystem/platform behavior remains unverified.
- 2026-10-13: Added Ctrl+N, Ctrl+F, and Ctrl+, shortcuts for the live Add, Search, and Settings UI. The Retry failed action now shows the selected queue's failed count and retries only that queue's tasks. Keyboard focus behavior and queue scoping remain runtime-unverified.
- 2026-10-13: Startup restoration now rebuilds the waiting queue oldest-first while the visible task history remains newest-first, preserving FIFO order across restart; equal-deadline retry timers are also re-armed in creation order. Ordering behavior remains runtime-unverified.
- 2026-10-13: Sidebar now exposes queue-scoped Active, Queued (including scheduled/retrying), Paused, Completed, Failed, History, and All views with matching state filters/counts; Active now means actual transfers rather than waiting work. UI/filter-count behavior remains runtime-unverified.
- 2026-10-13: HTTP 408 Request Timeout is now classified as transient for single-stream and segmented requests, using the existing bounded backoff/retry limit. HTTP 429 text no longer promises an automatic short retry when retry policy may prevent one. Network behavior remains runtime-unverified.
- 2026-10-13: Single-stream resume now accepts a valid finite `206 Content-Range` that ends before the known resource total, verifies the exact declared response byte count, and requests the remainder from the next flushed byte using the saved validator. Unknown `*` totals remain rejected for resumed ranges because completeness cannot be established. Runtime and capped-range response behavior remain unverified.
- 2026-10-13: Proxy tests, metadata probes, single-stream GETs, and segmented range requests now cap redirects at 10 while retaining Qt's no-less-safe redirect policy. Redirect-chain behavior remains runtime-unverified.
- 2026-10-13: Qt redirect-limit and insecure-downgrade errors now map to specific safe user messages instead of a numeric generic network error. FTP/SFTP dependency check: the installed Windows curl has FTP/FTPS but no SFTP and is not a bundled application dependency; no protocol support is claimed from it.
- 2026-10-13: The user-scoped single-instance local socket now limits each accepted connection's read buffer to 16 KiB plus one detection byte, matching its framed-message bound before JSON parsing. Oversized-socket runtime behavior remains unverified.
- 2026-10-13: Added an HTTP origin-authentication prompt for single-stream and segmented requests. Credentials are provided through Qt's `QAuthenticator`, retained only in process memory per task and canonical `(scheme, host, port)` origin, and never added to SQLite/settings; redirect origins require a separate prompt. Rejected credentials prompt again after the failed attempt, while closing the prompt leaves the task failed. Digest/basic challenge, retry races, and credential redaction remain runtime-unverified.

This is still an early P0 slice, not a complete product. Source and QML have not been compiled or run because the required Qt 6.12 MSVC kit is unavailable; CMake and Qt QML lint tools are also unavailable. SQLite initialization, startup restore, and task-save errors are surfaced in the UI, but database failure/recovery paths remain unverified; model/filter performance has not been measured.

Not implemented: advanced settings; FTP/SFTP; folder and playlist workflows; yt-dlp/HLS/DASH/FFmpeg; browser extension/paired bridge; update checks; installer; Linux validation. Segmented HTTP, extension-changing server filename adoption, tray/notifications, per-task destination changes, file/folder/custom-program completion actions, Windows Defender scan integration, and confirmed Windows shutdown/sleep/hibernate now have source implementations but need compile/runtime and failure-path verification. HTTP metadata probing, recurring scheduling, proxy, global bandwidth limiting, categories, and automatic category folders are implemented in source but need runtime/security verification. The initial local HTTP and queue integration coverage is incomplete and all Qt Test sources remain uncompiled and unexecuted.
