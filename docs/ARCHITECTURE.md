# Architecture

## Boundaries

- **Composition root:** `BestDM/main.cpp` creates the Qt application, manager, and QML engine.
- **Domain:** `BestDM/domain.h` owns the typed `DownloadState` and persistent `DownloadRecord` data.
- **Category rules:** `CategoryRules` parses user-editable extension/host rules and classifies new downloads without coupling rule behavior to QML or SQLite.
- **Network preferences:** `DownloadQueue` applies direct, system, or manual HTTP/SOCKS5 proxy configuration to its shared network manager. Proxy passwords stay in the Windows Credential Manager through `SecureCredentialStore`; other platforms allow unauthenticated proxy settings only.
- **Application model/facade:** `DownloadManager` is the QML-facing `QAbstractListModel`. It validates URL intake, provides roles and counters, assigns new tasks using editable extension/host category rules, maps row actions to queue operations, and persists application preferences through QSettings.
- **Orchestration:** `DownloadQueue` owns the task registry, waiting/active sets, concurrency cap, shared global bandwidth token bucket, startup recovery, bounded transient retry policy, recurring schedule-window enforcement, persisted scheduled retry state, active transfer duration for average throughput, and task persistence coordination.
- **Transfer engine:** each `DownloadTask` owns response validation, progress, speed, pause/cancel, and finalization. HTTP origin 401 challenges request credentials through the manager/QML prompt; Qt `QAuthenticator` receives them on retry, and the queue retains them in memory only for the running app session, keyed by task and canonical `(scheme, host, port)` origin. Redirects to a different origin therefore prompt separately. `SegmentedDownloader` issues bounded non-overlapping byte-range requests when the server advertises range support and a known size is available; segment files resume independently and merge in order through `QSaveFile`. Unsupported or mismatched ranges fall back to a single stream. Newly added URLs run a cancelable HEAD metadata probe before GET; safe server filenames can replace URL-derived names, and the queue reclassifies and re-reserves changed extensions before writing begins. App queue tasks share one thread-affine `QNetworkAccessManager` and consult the queue-owned bandwidth limiter.
- **Filesystem opens:** `openFileNoFollow` adopts OS-opened regular-file handles for partial writes, segment writes, and segment merge reads. The Windows path opens reparse points without resolving them and rejects reparse-point handles; POSIX uses `O_NOFOLLOW` and `fstat`. Parent directory traversal and post-close path replacement still require platform-specific review.
- **Persistence:** `PersistenceRepository` owns SQLite initialization, a transaction-wrapped schema migration through version 12, restore-all, upsert and remove. Task queue assignments and per-task overwrite intent live in SQLite; named queue definitions, selected queue, and the default Rename/Ask/Overwrite preference live in QSettings.
- **Persistence errors:** repository initialization, restore-query/iteration, and task-save errors flow through the manager's visible error state. Startup reconciliation remains fail-visible; SQLite corruption and disk-full workflows still need runtime verification.
- **Diagnostics:** `DiagnosticLogger` installs a Qt message handler and writes redacted messages to a bounded application-local log with up to three rotated backups. Settings offers a user-selected text export of those logs only, reapplying redaction and excluding task/database data.
- **Platform services:** `TrayController` owns the native Qt system tray menu, window restore and local notifications; `DownloadManager` gates minimize-to-tray and notification settings and receives task state changes.
- **Presentation:** `BestDM/main.qml` renders the model, distinct Active/Queued/Paused/Completed/Failed/History navigation filters and per-queue counts, search, task actions, batch intake, theme, queue concurrency, per-download connection settings and close/minimize-to-tray behavior. Transfer and database logic remain in C++.
- **Task destination changes:** inactive tasks and completed outputs may be moved to another existing writable folder. The queue reserves a collision-free name, migrates final output, `.part`, and segment files using rename or cross-volume copy with rollback, updates the persisted base destination, and disables automatic category-folder routing for that task.

## Current task flow

Adding a URL validates HTTP/HTTPS syntax, allocates a stable ID and collision-free name, copies the configured per-download connection count and overwrite intent into the record, inserts a visible queued row, persists it, and gives it to the queue. The scheduler starts tasks up to the configured active cap. Task events update the queue's canonical record, SQLite, and then the model row. A pause retains either the `.part` or independently recoverable segment files; cancel applies the selected cleanup policy to both. Rename and Ask/Rename completion use an OS no-replace publication primitive; if another process claimed the reserved filename during transfer, they choose another suffix and update the displayed filename. Explicit Overwrite uses atomic replacement only after successful transfer validation. Selected transient network failures and HTTP 429/500/502/503/504 responses receive exponential delayed retries, bounded by the persisted user retry limit. Retry state and next-retry time survive application restart; restored retry tasks re-arm their deadline. The Retry failed toolbar action is scoped to the currently selected queue.

At startup, SQLite records are loaded newest-first for history display. In-flight states become paused when a partial exists and failed when it does not. Paused byte counts are reconciled against current partial/segment files, with a visible note when resume must restart from zero. Missing destination folders for incomplete tasks are recreated when possible; unavailable destinations become visible failed records. Completed history is retained. Persisted queued entries are restored oldest-first into the FIFO waiting list, and persisted retry deadlines re-arm their retry timers in creation order.

## Destination capacity and resume safety

Known-size transfers check destination free space before writing; segmented transfers also account for the temporary final file needed by atomic merge. Writes and flushes still handle runtime storage failures because available space can change after preflight. Recoverable partial files remain available, and disk-write failures do not enter the transient network retry path.

A partial-file resume sends `Range` and `If-Range` when ETag or Last-Modified is known. Appending is allowed only for HTTP 206 with a syntactically valid Content-Range whose start equals the saved offset. Known resource size and validators must still match. HTTP 200 restarts the partial at zero. HTTP 416 or changed validators/known totals truncate and retry from byte zero. Other status/range mismatches abort. TLS checks remain at Qt's secure default.

## Persistence and threading

SQLite saves state names at the repository boundary while domain code uses the enum. Schema setup and migration are executed in a transaction. Networking is asynchronous and currently lives on the application thread; file writes are streamed in ready-read events. Transfers abort after 30 seconds without data. SQLite progress writes are coalesced to at most one per task every 500 ms, while model updates still follow network progress events. Build/runtime verification remains pending because the local Qt 6.12 kit and CMake are absent.

## Security limits

`SingleInstanceCoordinator` owns the user-scoped local socket endpoint and validates forwarded HTTP(S) URLs before emitting them. `ApplicationProtocol` parses the custom action and owns the Windows HKCU registration. The composition root forwards accepted URLs to `DownloadManager`, which validates again and emits them to QML; QML presents them in the existing Add dialog. Protocol intake never calls the enqueue path directly. Registration and local endpoint ACL behavior remain unverified in a Windows runtime.

Only HTTP/HTTPS links are accepted. TLS validation is not disabled. URL-derived filenames are reduced to safe basenames, Windows reserved names are prefixed, and names are collision checked against disk and active/history records. Rename is the default; Ask can review conflicts known before enqueue, and explicit Overwrite replaces only unmanaged outputs after successful transfer validation. If a server later supplies a conflicting Content-Disposition filename, the queue safely picks a suffix. Logs redact URL query data, auth-like fields, and the home path; regression tests and runtime behavior remain unverified. Ancestor reparse-point handling and platform credential-store review also remain open.
